每个 owner 的 `records/<experiment_id>/summary.json` 是该实验唯一的 canonical machine scope；原始 `exp_*`、checkpoint、raw response 和完整文档不进入普通 Git 仓库。当前实验归属与 claim 使用以 [`EXPERIMENT_INDEX.md`](./EXPERIMENT_INDEX.md) 为准；结论解释与研究进度分别以 [`FINDINGS.md`](./FINDINGS.md) 最新编号条目和 [`RESEARCH_JOURNAL.md`](./RESEARCH_JOURNAL.md) 最新实验小节为准。

**三层管线一句话**：文档(bytes) → struct2 切块 → prompt（全文+索引+4 路径 schema）→ LLM 输出信封 JSON(+[FILE BODIES]) → 确定性执行器应用（未声明块逐字节保留）→ 领域评估器打 RS。与 FullRewrite 在同一 seeded 任务序列上配对比较，核心研究问题是 **HybridPatch 能否整体上优于 FullRewrite**；strict38 的 clean-transport 结果没有建立这一强主张，见 §6。

**指标速查**：RS（0–1 重建分）；RS@k（第 k 轮往返的 backward RS）；配对 Δ（同任务 plan 下 HP−FR 的 backward 均值差）；CF@10（CriticalFailure：相邻轮 RS 跌幅 > θ=0.10 的行数/RT2-10 总行数）；kept-context（失败步保留原文档、显式记失败）；bounded_rewrite 份额（路由身份稀释披露）；`preservation_violations`（未声明块被改，**恒须为 0**）。

## 3. 迭代编年史

每轮统一按五问记录：**① 为什么（问题来源）② 优化方向 ③ 效果 ④ 引入/暴露的新问题及是否解决 ⑤ 下一轮的靶子（新问题还是残留）**。

### 3.1 hybridpatch/3 —— 快照定位 + repair 扩类（§216–§217）

**① 为什么**：全部来自上一轮（think5）新暴露的两个问题——occurrence 漂移（执行器语义缺陷）与 repair 盲区（策略缺口）。

**② 方向**：
- local_patch **快照语义**：所有 op 的 occurrence/唯一性一律按**步骤输入文档**（模型在 prompt 里看到的那份）解析；span 互不重叠校验后右到左一次性应用——"模型看到的编号就是最终编号"。
- repair 触发从 invalid_json/schema **扩展到任何可精确描述的失败**（op 拒绝/route violation/空输出/gate 失败），repair prompt 携带 [TASK]+[EDITABLE DOCUMENTS] grounding、允许补发 [FILE BODIES]。
- 版本门控纪律自此定型：语义改动走新 protocol rev，旧归档必须字节级复现。

**③ 效果**（exp_20260708_hybridv3dev20full，dev20×双臂×10RT，结果复核：39/40 样本字节级复现 + 1 处已知评估器非确定性）：
- headline 配对 Δ**+0.225**（n=200，HP 0.910 vs FR 0.685，t=7.55，d=0.53）；CF@10 5/180 vs 10/180。
- **但归因发现 ¾ 的优势是 provider 伪影**：6 个 FR 样本被"thinking-runaway 空返回"毒化整链；剔除后 14 样本 Δ 塌到 +0.051。对 5 个空返回样本 rewind 重跑后 Δ 收敛到 **+0.141**（t=5.43，d=0.38），再剔除仍随机复发的 3 样本 Δ=+0.048（17 样本）。
- 空返回率两臂均等（HP 1.6% vs FR 1.5%），差异在**承接架构**：HP 的空全部被 repair 第二调用或 kept-context 吸收（零链毒化），FR 无护栏、一次空即毒化全链。这成为方法主叙事（灾难规避/优雅降级是结构性优势）的第一个定量形态。
- 上游对齐审计：与官方 DELEGATE52 逐文件核对，FR 空毒化是 authentic baseline 行为；顺带发现并补齐 runner 缺失的 `validate_wildcard_context` 分支（6 个 forward 行改判、HP/FR 完美对称、配对零影响）。

**④ 新问题（本轮暴露）**：
- **bulk_patch 跨块匹配缺口**（docker6 RT3、fonteng3 RT1）：锚点整文件唯一但跨 struct2 块边界——local 在 v2 已改文件级匹配、bulk 没跟上，协议内部不一致。→ **v4 解决**。
- `@body:` 哨兵内嵌空白（mathlean2 RT2 `\n\n`）→ body_ref_not_found。→ **v4 解决**。
- `_unescape_ws` 把 `\ref`/`\rho` 的 `\r` 误转 CR，空白容错阶梯对 LaTeX 失效。→ **v4 解决**。
- 身份稀释量化：bounded_rewrite 份额 74.2%、离线测算 22% 的 bounded 输出 ≥80% 可整行复制（"为改几行重写整文件"）。→ v4 P1 路由压强。
- 结果复核有 1 处 MISMATCH（quantum4 RT9 stored 0.985 vs recomputed 1.000）：评估器 AST/regex 双路径环境敏感、recompute 更高＝stored 保守，**非造假**；作为已知预存差值随归档携带。

**⑤ 下一轮靶子**：全部是本轮新暴露项（D1 bulk 文件级 / D2 body-ref 归一 / D3 ws 两趟）+ 身份稀释残留（P1 路由压强）。

### 3.2 hybridpatch/4 —— bulk 对齐 + 路由压强（§218–§219）

**① 为什么**：v3 轮的 D1/D2/D3 三个执行器缺口 + P1 身份稀释（残留自 §213 "补丁路径贡献近零"）。

**② 方向**：bulk 文件级匹配+右到左跨块应用；`@body:` 哨兵空白归一化；ws 阶梯两趟化（原文 token 优先）；prompt 加路由压强"按编辑足迹路由——大部分行不变的文件必须走 local/bulk，禁止重写"。

**③ 效果**（exp_20260709_hybridv4smoke，7 个靶样本 × HP 单臂 × 10RT，与 v3 同任务序列纵向对照；结果复核 PASS 70/70）：
- **机制目标全数达成**：kept-context 0/140（v3 在同集合恰好含全部 5 个 kept 案例）、forward no-op 0/70、gate 失败 0、repair 6/6 全采用。
- 逐样本全程均值（v4/v3/Δ）：docker6 **0.968/0.804/+0.164**、malware6 **1.000**/0.915/+0.085、latex2 0.986/0.934/+0.052、fonteng3 0.888/0.862/+0.026、geotrack3 0.830/0.842/−0.012、mathlean2 0.740/0.900/**−0.160**、foodmenu6 0.800/0.995/**−0.195**；聚合 0.887 vs 0.893（表面持平）。
- P1 路由位移显著：patch 路由 39.3%→**59.8%**，生成字节占比 0.534→**0.418**。成本结构洞察：patch 信封省正文字节、但模型构造 op 想得更久——成本从 text 挪到 thinking（总账 +1.6%）。

**④ 新问题**：
- **mathlean2 −0.160 ＝ delete 语义误用 + repair 放大**：模型把"定位上下文+待保留声明头"整段塞进 delete 的 old_text，执行器忠实删掉 8 个声明头；**repair 是放大器**——初版 2 op not_found 本会 kept-context 冻结在 ≈0.9，repair 补齐后 10 个破坏性 op 全部命中。→ F3 prompt 一句话（v5 落地）；repair 采纳闸列为候选（F2，后续两轮审计均零负例，至今未出手）；根子是模型能力类，**缓解未根治**。
- **foodmenu6 −0.195 ＝ 评估器可见性彩票，非回归**：同一语义偏差两轮都在，v4 碰巧用了评估器正则可见的 `--- X ---` 标题（被扣分），v3 用 `== X ==` 正则不可见（1.00 是假阴性）。→ 记 F4 基准注意，**非方法问题**。
- **fonteng3 RT7 0.77 ＝ 模型自毁撤销线索**：forward bulk 在**变异中缓冲区**顺序执行，把自己刚插入的改名映射注释也改写退化，backward 信任被毒化注释。执行器侧成分（顺序变异语义）→ **v5 解决**；模型侧成分（自加装饰性 op）后续演化为 v7 的靶子。

**⑤ 下一轮靶子**：本轮新问题的执行器成分（F1 bulk 快照）+ prompt 缓解（F3 delete 语义）；F2 repair 双刃剑挂起观察。

### 3.3 hybridpatch/5 —— bulk 快照 + P1 全量验证（§220–§221）

**① 为什么**：F1/F3 来自 v4 smoke 新暴露项；同时 P1 路由压强需要全量 dev20 检验（smoke 的 7 样本偏 patch 友好）。

**② 方向**：bulk_patch 快照定位（匹配与 expected count 全按步骤输入文档；跨 op span 冲突显式拒绝、同行 delete 去重；与 local v3 同构）；delete 语义 prompt 一句话。

**③ 效果**（exp_20260709_hybridv5dev20full，dev20×双臂×10RT；结果复核 PASS 400/400）：
- 配对 Δ**+0.035**（n=200，t=1.41，**不显著**）；剔除 3 个 FR 仍污染样本后 Δ+0.004——**本轮方法效应归零**（v3 轮同口径 +0.048）。CF@10 10/180 vs 12/180。
- 身份指标显著改善并保持：bounded 份额 **57.5%**（v3 74.2%）、生成字节占比 **0.595**（v3 0.716）、字节保留率 0.341（v3 0.251）；kept-context 7/400（1.8%）。
- 成本：HP 15.86M vs FR 7.81M tokens。

**④ 新问题（本轮引入/暴露，全部执行器无罪、字节级 replay 确认）**：
- **P1 伤亡 #1 quantum4 0.989→0.426**：被压到 bulk 后清理 op 字面量差 3 字符，吃掉 6 行注释标记→QASM AST 解析失败→12 字节伤害被评估器放大成 −0.61。→ **v6 C2 解决**。
- **P1 伤亡 #2 starcatalog4 0.984→0.757**：被压到 local 后模型造出自相矛盾的列编辑，结构合法、纯语义错列——reference-free 检查拦不住。→ **不可修类**（无参考不可判），后续以随机形态反复出现。
- **protein1 0.955→0.285**：bounded 重建定宽 PDB 时 2 行多 1 空格→Biopython 整文件弃解析→归零。暴露 **gate 设计缺口：无可解析性检查**。→ **v6 C2 解决**。
- **circuit2 1.000→0.898 ＝ v5 自伤**：新加的重叠拒绝把"删行 span 包含 replace span"这种语义完全可组合的形态也拒了（v4 顺序语义 4/4 全收 RS=1.0），kept-context 0.886 卡死 9 轮。→ **v6 C1 解决**。
- fonteng3 本轮任务序列未触发 RT7 形态，F1 的正向效果无直接证据（后来在 v7 轮同位复发时得到验证）。

**⑤ 下一轮靶子**：全部是本轮新伤——C1 包含型重叠消解（circuit2）、C2 无参考格式健康 gate（quantum4+protein1 两类）；C3（P1 措辞逃生口）评估后缓行。**净判定定调**：路由压强的代价首次量化——patch 路径暴露了模型手写精确字面量的能力短板，且 relay 的棘轮性质使被接受的字节伤害永久化。

### 3.4 hybridpatch/6 —— C1+C2 修复 + FR 基线冻结 + val40 验证（§222–§225、§227）

**① 为什么**：C1/C2 直接对应 v5 的四大伤亡中可确定性修复的三个（circuit2/quantum4/protein1）；starcatalog4 类承认不可修。

**② 方向**：
- C1：删行 span **完全包含** replace span 时吞并（净结果=v4 顺序语义），部分重叠与 replace-replace 重叠仍拒。
- C2：**无参考格式健康 gate**——扩展名 lint 注册表（json/xml/kml/gpx/svg/qasm/pdb），"输入可解析则输出不得回退"、新建 lintable 文件绝对判定；命中走既有单次 repair，再败 kept-context。
- 上线前设计证明：把 v6 gate 离线套在 v5 campaign 全部 400 步——仅 8 步命中、全部属于 quantum4/protein1 真实损伤链，**误报 0/400**。

**③ 效果**：

## 5. 平行线：传输层迭代（同样一轮轮"发现问题→修→验证"）

方法迭代之外，provider（MiniMax-M3 @ OpenCode Go）的病理逼出了四轮传输层改造：

1. **SSE 流式化**（Journal §4.4，v2 时代）：thinking + 非流式 + Cloudflare 120s = 524 结构性死亡（重试全撞同一堵墙）→ 改 SSE 流式，字节持续流动。教训：先分辨瞬态错误与结构性错误再谈重试。
2. **transport-v2**（§229）：val40 的机制发现（服务端 thinking 中途断流）证明"HTTP 200 + 收到 token ≠ 完成"→ 切 Anthropic SDK `messages.stream()`，完成判据 = message_delta + message_stop + final usage 齐全；≤3 总 attempt；raw 日志线性化（修复 SDK 累计 snapshot 的 O(n²) 写放大：1.12GB→8.6MB）；新增 monitor。E2E smoke 结果复核 PASS 20/20（诊断性，不作方法结论）。
3. **transport-v3 公平性冻结**（§230、[`transport/docs/API_TRANSPORT_FROZEN_V3.md`](../transport/docs/API_TRANSPORT_FROZEN_V3.md)）：v2 把所有异常压成一个 retry 数、且换 Key/重启可刷新预算（隐形额外采样）→ v3 按 semantic call 双预算（**2 个 response slot + 3 个生成前 transient failure**，跨进程持久化）；attempt ledger + 原子 response journal（崩溃回放不重复计费）；**完整空/thinking-only 按 Baseline 模型失败计分，不 retry 不 repair**。零 API 测试 26/26 + 真实 v2 异常 fixture 回放 + 11-Key canary + 双臂 smoke（result verification 20/20）通过后冻结。
   - **对实验口径的直接后果**：正式比较必须两臂同 v3 fingerprint、新 out_dir——**旧 transport 的 FR 基线降级为历史/敏感性分析**，为哪个集合做正式比较就为该集合冻结一份 FR-v3。
4. **transport-v4 流失败分类与样本级隔离**（[`transport/docs/API_TRANSPORT_V4.md`](../transport/docs/API_TRANSPORT_V4.md)；[paired10 summary](../HP_V8/analysis/exp_20260718_hybridv8_transportv4_snapshotfix_paired10.md)）：HTTP 200 `Streaming response failed` 先按 incomplete stream 识别；R2/I3 按实际 delta 事件记账；只有四证一致的 provider exhaustion 才隔离单样本，preservation/Git/重复/半提交/映射/local/evaluator 错误仍全局停止。snapshotfix paired10 在主机断电后只续三个未完成样本，旧 committed prefix 0 POST，最终 400/400、strict inspector PASS。该 host-loss reconciliation 有独立 artifact，但不是 v4 自动恢复能力的泛化证明。

3. 只有确认存在可泛化、可证伪的新假设后，才创建 **HP_V9**。不在 active HP_V8 内继续叠加方法语义，也不为提示字符数单独牺牲有效路径。

**承认并持续披露的边界**：starcatalog4 类无参考语义错列、bounded 重建抽签类（musicsheet2/translation4/satellite6）、任务性有损 schema（geotrack3）、评估器彩票（foodmenu6）、不可逆任务（genealogy6、fonteng3 GDEF 段）。
